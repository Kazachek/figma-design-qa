**Стадія:** розробка

# Про проєкт

Публічна копія скілу `figma-design-qa` (GitHub `Kazachek/figma-design-qa`): сам скіл, інструкція для нових людей (`README.md`), реліз-нотси (`CHANGELOG.md` і GitHub Releases). Скіл знімає з дизайнерів рутину у Figma через Figma MCP; зараз уміє лише гігієну шарів і найменувань. Для людей, у яких Figma MCP уже налаштований, — налаштування MCP тут не описуємо.

# Дві копії скілу

- **Робоча** — `~/.claude/skills/figma-design-qa`: нею Кирило користується й тестує. Бекап — приватний `Kazachek/claude-skills`.
- **Публічна** — `figma-design-qa/` тут. Не все, що тестується локально, йде в реліз.
- Правимо робочу копію. Після кожної зміни спитай, чи синхронізувати її сюди. Якщо так — скопіюй `SKILL.md` (і інші файли скілу, якщо з'являться), додай рядок у `CHANGELOG.md` під `## Ще не випущено`, онови `README.md`, якщо зміна його стосується.
- Публічну копію напряму не правимо, інакше наступна синхронізація затре правку.

# Робочий процес

- **Коміти:** коротко опиши, що закомітиш, дочекайся «так», закоміть і одразу запуш у `origin/main`.
- **Версії:** `MAJOR.MINOR.PATCH`, тег `vX.Y.Z`. У кожному звіті про коміт — рядок «Версія: X.Y.Z (+N після неї)» з `git describe --tags --match 'v*'`.
- **Нагадування про версію:** коли після останнього тегу накопичились зміни для людей — запропонуй випуск і номер. «Накопичуємо» — не випускати.
- **Випуск** (лише після «Випускай X.Y.Z»): у `CHANGELOG.md` заміни `## Ще не випущено` на `## X.Y.Z — дата`; коміт `Release X.Y.Z`; тег `vX.Y.Z`; push разом із тегом; `gh release create vX.Y.Z` з тими ж нотатками.
- **Тексти** (README, CHANGELOG, сам скіл) — українською, бо для них і пишемо.
