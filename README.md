# figma-design-qa

Скіл для Claude, який знімає з дизайнера рутину гігієни шарів і найменувань у Figma. Він сам знаходить назви, які ставлять Figma та інші програми (`Frame 427`, `Rectangle 12`, `Group 15 copy copy`, `Clip path group`, імена вставлених файлів тощо), і перейменовує їх на зрозумілі українські — без зайвих питань. Назви, які ти дав сам, він не переписує, а лише чистить: виправляє помилки, перекладає англійське й ставить велику літеру. Компоненти не чіпає.

Що змінилось у кожній версії — у [CHANGELOG.md](CHANGELOG.md) і в [Releases](https://github.com/Kazachek/figma-design-qa/releases).

## Що потрібно

- Claude з уже підключеним і авторизованим **Figma MCP** (разом з ним іде скіл `figma-use`, яким цей скіл користується для перейменування).
- Права на редагування файлу у Figma — інакше скіл не зможе перейменувати шари.

## Як підключити скіл

**Claude Code** (термінал або вкладка Code у застосунку Claude). Скопіюй папку `figma-design-qa` з цього репозиторію в `~/.claude/skills/`:

```bash
git clone https://github.com/Kazachek/figma-design-qa.git ~/figma-design-qa-repo
```

```bash
cp -R ~/figma-design-qa-repo/figma-design-qa ~/.claude/skills/
```

Без терміналу: **Code → Download ZIP** на сторінці репозиторію, розпакуй і поклади папку `figma-design-qa` в `~/.claude/skills/`. Скіл підхопиться в наступній сесії Claude.

**Оновлення:** заміни папку `~/.claude/skills/figma-design-qa` новою версією (або `git pull` у клоні й ще раз `cp`). Що нового — у [CHANGELOG.md](CHANGELOG.md).

## Як почати роботу з файлом Figma

1. У Figma виділи фрейм, з якого почати.
2. Правою кнопкою → **Copy/Paste as → Copy link to selection**.
3. Встав посилання в чат з Claude і скажи, що треба, наприклад:
   - «Причеши назви шарів тут: <посилання>»
   - «Прибери Frame 427 і подібне сміття: <посилання>»

Що буде далі:
- Claude почне з фрейма з посилання, потім пройде всю його сторінку, потім решту файлу. Якщо файл великий, після сторінки він зупиниться й спитає, чи продовжувати.
- Шари з дефолтними назвами він перейменує сам, нічого не питаючи. Назви — українською, з великої літери, за роллю шару: `Шапка`, `Картка товару`, `Кнопка / Купити`, `Іконка / Стрілка вниз`, `Фон`.
- У назвах, які дали люди, він виправить помилки (`Заголовк` → `Заголовок`), перекладе англійське (`hero` → `Головний блок`, бренди на кшталт `iPhone` лишаються) і поставить велику літеру.
- Обгортки без тексту отримують назву за вмістом: фрейм навколо шару «Картка» стає `Обгортка / Картка`.
- Якщо шар справді порожній і зовсім незрозуміло, що це, назва може вийти жартівливою: `Казна-що`, `Дідько його знає`, `Хто це сюди поклав`. Це знак, що на шар варто глянути.
- Наприкінці ти отримаєш короткий список «було → стане». Шари, де Claude не впевнений (зокрема з жартівливими назвами), він покаже окремо й запропонує назвати інакше або відкотити.
- Щоб повернути старі назви, скажи «відкоти все» або «відкоти 3».

Що він не чіпає ніколи:
- компоненти й інстанси, локальні й з бібліотеки, разом з усім, що всередині них;
- зміст назв, які ти чи хтось інший дали руками;
- нутрощі ілюстрацій, іконок і лого: таку графіку він називає цілком, а тисячі `Vector` усередині лишає як є;
- текстові шари, назву яких Figma сама тримає рівною тексту;
- набір шарів і їхнє положення: нічого не видаляє, не додає, не переміщує й не групує, навіть порожні фрейми. Міняє лише назви.

## Що далі

Зараз скіл уміє тільки гігієну шарів і найменувань. У планах — QA-чекліст перед здачею, аудит текстів і підготовка хендофу для розробки.
